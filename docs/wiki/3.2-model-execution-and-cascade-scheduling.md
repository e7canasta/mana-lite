# Model Execution and Cascade Scheduling
Este documento técnico detalla el funcionamiento de **mana-lite**, un sistema avanzado de inferencia que organiza la ejecución de modelos de IA mediante una **estructura de cascada**. El proceso es coordinado por el **InferEngine**, el cual gestiona todo el ciclo de vida de los modelos, desde la validación de tareas hasta el **procesamiento de imágenes** mediante recortes estáticos o dinámicos para mejorar la precisión. Un componente esencial es el **Cascade Scheduler**, encargado de activar modelos "hijos" de forma condicional basándose en los hallazgos de los modelos principales, permitiendo análisis profundos solo cuando se detectan entidades específicas. Finalmente, el sistema emplea una **consolidación de detecciones** y filtros de post-procesamiento para fusionar resultados, eliminar duplicados y garantizar una observación final coherente y de alta calidad.

The inference pipeline in `mana-lite` is a multi-stage process that manages the lifecycle of YOLO models, schedules their execution based on parent-child dependencies (cascades), and processes raw outputs into consolidated detections. The system supports both static ROI (Region of Interest) filtering and dynamic cropping for high-resolution analysis of specific entities.

## InferEngine Lifecycle

The `InferEngine` is the central coordinator for model execution. It abstracts the underlying inference backend (typically `ultralytics-inference`) and manages the pre-processing, prediction, and post-processing stages.

### Initialization

The engine is initialized via `InferEngine::from_catalog`, which iterates through the `ModelCatalog` to load enabled models [infer/mod.rs62-78](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L62-L78)

- **Model Loading**: Each model is loaded using `YOLOModel::load_with_config` [infer/mod.rs182](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L182-L182)
- **Task Validation**: The engine verifies that the task defined in the catalog (e.g., `Detect`, `Segment`, `Pose`, `Depth`) matches the actual task reported by the ONNX model [infer/mod.rs194-200](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L194-L200)
- **Static ROI**: If a model has a `CropType::Static` configuration, a `CropRect` is pre-calculated and applied to every inference call [infer/mod.rs166-179](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L166-L179)

### Execution Flow (`run`)

The `run` method executes a single inference cycle for a specific model [infer/mod.rs84-140](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L84-L140):

1. **Preparation**: `prepare_infer_image` handles image cropping and coordinate offset calculation [infer/mod.rs96-97](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L96-L97)
2. **Prediction**: The model performs inference, returning raw `ultralytics_inference::Results` [infer/mod.rs98](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L98-L98)
3. **Depth Extraction**: If the model produces depth maps, they are extracted immediately to avoid unnecessary copies [infer/mod.rs108](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L108-L108)
4. **Detection Collection**: Raw boxes, masks, and keypoints are parsed into `Detection` structs [infer/mod.rs109-114](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L109-L114)
5. **Coordinate Translation**: Detections are translated from the crop/ROI space back to the original frame coordinate system [infer/mod.rs115](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L115-L115)
6. **Filtering & NMS**: Detections undergo static ROI filtering, `PostprocessConfig` filtering (confidence, area, class), and Non-Maximum Suppression (NMS) [infer/mod.rs116-128](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L116-L128)

**Sources:** [infer/mod.rs47-145](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/mod.rs#L47-L145) [infer/run_helpers.rs130-205](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/run_helpers.rs#L130-L205)

## Cascade Scheduling

`mana-lite` uses a cascade system to trigger "child" models based on the output of "root" models. This is commonly used to run a specialized face detector only when a person is detected in the room.

### Scheduling Logic

The `App::run_inference` loop orchestrates the cascade [app/inference.rs35-69](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/app/inference.rs#L35-L69):

1. **Root Models**: Models with no `requires` parent are executed first [app/inference.rs72-91](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/app/inference.rs#L72-L91)
2. **Child Models**: Models that depend on a parent are executed only if the parent produced a valid target [app/inference.rs94-118](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/app/inference.rs#L94-L118)
3. **Target Resolution**: The `CascadeScheduler` determines the `CropRect` for the child model by looking at parent detections in the current frame or confirmed tracks from the previous frame [app/inference.rs130-159](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/app/inference.rs#L130-L159)

## Static vs. Dynamic Cropping

The system employs different cropping strategies to optimize for both performance and accuracy.

|Strategy|Implementation|Use Case|
|---|---|---|
|**Static ROI**|`CropRect` + `apply_static_roi_filter`|Restricting inference to a fixed region (e.g., a doorway) to reduce false positives.|
|**Dynamic Crop**|`extract_crop_frame`|Extracting a sub-region of the frame for high-resolution child inference.|
|**Class ROI**|`compute_largest_class_roi`|Cropping around the largest instance of a class (e.g., "person").|
|**Upper Square**|`compute_upper_square_roi`|Centering a square crop on the upper body/head of a person for face detection.|

### ROI Computation Functions

- **`compute_largest_class_roi`**: Finds the largest detection of a target class and applies a margin [infer/crop.rs46-85](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/crop.rs#L46-L85)
- **`compute_upper_square_roi`**: Specifically designed for face cascades. It calculates a square region based on a fraction of the parent bounding box's height to ensure the face is captured even if the person is moving [infer/crop.rs136-174](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/crop.rs#L136-L174)
- **`extract_crop_frame`**: Performs the actual pixel-level crop from the RGB buffer [infer/crop.rs6-44](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/crop.rs#L6-L44)

**Sources:** [infer/crop.rs1-174](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/crop.rs#L1-L174) [core/mana-perception/src/detection.rs11-31](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/core/mana-perception/src/detection.rs#L11-L31)

## Detection Consolidation and NMS

After all models in the cascade have run, the `DetectionConsolidator` fuses the outputs.

### Consolidation Workflow

1. **Same-Class Merge**: Detections of the same class from different models are merged if their IoU exceeds `same_class_iou` [core/mana-perception/src/detection.rs141-176](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/core/mana-perception/src/detection.rs#L141-L176)
2. **Component Attachment**: Specialized logic attaches "face" detections to "person" detections based on `face_component_coverage` and vertical positioning (`face_max_center_y_ratio`) [core/mana-perception/src/detection.rs178-199](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/core/mana-perception/src/detection.rs#L178-L199)
3. **Evidence Tracking**: The final `ConsolidatedObservation` retains a list of `DetectionEvidence` from every model that contributed to it [core/mana-perception/src/detection.rs90-97](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/core/mana-perception/src/detection.rs#L90-L97)

### Post-Process Filtering

The `PostprocessConfig` (defined in `models.toml`) is applied to filter out low-quality detections before they reach the consolidator:

- **`apply_nms`**: Standard Non-Maximum Suppression using the model's configured `nms_iou` [infer/run_helpers.rs126](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/run_helpers.rs#L126-L126)
- **`apply_postprocess_filter`**: Filters by `min_confidence`, `min_area_ratio`, and `max_area_ratio` [infer/run_helpers.rs81-128](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/infer/run_helpers.rs#L81-L128)
