Este documento técnico detalla la etapa de **Consolidación de Detecciones**, un proceso crítico que unifica los resultados de diversos modelos de inteligencia artificial en una observación coherente antes de enviarla al sistema de control. El flujo de trabajo utiliza un motor lógico para **fusionar detecciones de la misma clase** basadas en su solapamiento espacial y para **vincular subcomponentes**, como rostros, a sus entidades principales basándose en reglas de cobertura y posición vertical. Además de la visión, el sistema integra **estadísticas de profundidad por región** para calcular métricas precisas sobre el entorno físico mediante el análisis de píxeles válidos y percentiles de distancia. Finalmente, toda esta información se empaqueta en una estructura denominada **ClinicalSample**, la cual actúa como el puente informativo final que garantiza que los datos procesados sean útiles para la toma de decisiones del software.

The **Detection Consolidation** stage is the final phase of the inference pipeline before data is handed off to the control system. Its primary purpose is to fuse outputs from multiple models (e.g., a general room model and a specialized face model) into a single, coherent set of observations. This process handles overlapping detections of the same class and attaches sub-components, such as faces, to their parent entities (persons).

## DetectionConsolidator Implementation

The `DetectionConsolidator` is a stateless engine that processes `ModelDetections` in a single cycle [core/mana-perception/src/detection.rs113-117](core/mana-perception/src/detection.rs#L113-L117) It performs two main types of fusion:

### 1. Same-Class IoU Merging

If multiple models detect the same object (e.g., two different models both detect a "person"), the consolidator merges them into a single `ConsolidatedObservation` if their bounding box Intersection over Union (IoU) meets or exceeds the `same_class_iou` threshold (`iou >= same_class_iou`) [core/mana-perception/src/detection.rs141-164](core/mana-perception/src/detection.rs#L141-L164)

- **Primary Model Priority:** If a detection comes from the app-level `primary_model` (resolved from the blueprint's `inference.default_model`), its bounding box coordinates take precedence — granted on the **first** primary contribution to an observation; later primary contributions do not re-override [core/mana-perception/src/detection.rs167-172](core/mana-perception/src/detection.rs#L167-L172)
- **Confidence:** The resulting observation takes the maximum confidence score among all merged detections [core/mana-perception/src/detection.rs173](core/mana-perception/src/detection.rs#L173-L173)

### 2. Face-to-Person Attachment

The system treats faces as components of a person rather than independent entities. A `face` detection is attached to a `person` observation if it satisfies three spatial constraints:

1. **Coverage:** The face box must be largely contained within the person box, exceeding `face_component_coverage` [core/mana-perception/src/detection.rs182-185](core/mana-perception/src/detection.rs#L182-L185)
2. **Vertical Position:** The face must be in the upper portion of the person's body, governed by `face_max_center_y_ratio` [core/mana-perception/src/detection.rs186-190](core/mana-perception/src/detection.rs#L186-L190)
3. **Suppression:** Faces are never emitted as standalone observations — every unattached `face` detection is suppressed regardless of whether an attachment occurred in that cycle [core/mana-perception/src/detection.rs201-203](core/mana-perception/src/detection.rs#L201-L203)

## Data Structures

### ConsolidatedObservation

This structure represents a fused entity. It maintains a list of `DetectionEvidence` (the original raw detections that contributed to this fusion) and `components` (sub-entities like faces).

|Field|Type|Description|
|---|---|---|
|`class`|`String`|The resolved class name (e.g., "person").|
|`confidence`|`f32`|The highest confidence score from all evidence.|
|`bbox`|`[f32; 4]`|The bounding box in global frame coordinates.|
|`primary_model`|`String`|The ID of the model providing the primary geometry.|
|`evidence`|`Vec<DetectionEvidence>`|List of all detections merged into this entity.|
|`components`|`Vec<DetectionEvidence>`|List of sub-components (e.g., faces) attached.|

**Sources:** [core/mana-perception/src/detection.rs89-97](core/mana-perception/src/detection.rs#L89-L97)

### ClinicalSample

The `ClinicalSample` is the bridge to the control system. It contains the consolidated observations and metadata about the inference cycle's health.

- **`signal_valid`**: Indicates that the primary root model produced a result this cycle (`run_scheduled_model` returned `Some`) — note it is `true` even when that result contains **zero** detections; it does not imply anything was detected [src/app/inference.rs83-90](src/app/inference.rs#L83-L90)
- **`raw_person_count`**: A pre-calculated count of persons used for rapid occupancy checks [src/app/inference.rs58](src/app/inference.rs#L58-L58)
- **`face_model_ran`**: Boolean flag indicating if a specialized face model was executed in this cycle [src/app/inference.rs48-50](src/app/inference.rs#L48-L50)

**Sources:** [src/app/inference.rs17-24](src/app/inference.rs#L17-L24)

> Segmentation masks are carried on detections as `DetectionMask` (RLE `CompactMask` + normalized polygons) and translated to frame coordinates in the inference stage — see `core/mana-perception/src/detection.rs:58-76`.

## Depth Sensing and Region Statistics

After consolidation, depth data is processed per depth model through `region_stats` (in `record_model_result → record_depth_result → evaluate_depth_rules`). This function computes statistics for specific rectangular regions of the `DepthFrame`.

### Depth Processing Logic

The `region_stats` function calculates:

- **Valid Pixels:** Count of pixels with finite, non-zero depth values [core/mana-perception/src/lib.rs50-57](core/mana-perception/src/lib.rs#L50-L57)
- **Percentiles:** `min`, `max`, `median`, `p10`, and `p90` depth in meters [core/mana-perception/src/lib.rs81-86](core/mana-perception/src/lib.rs#L81-L86)
- **Valid Ratio:** The percentage of the requested region that contains valid depth data [core/mana-perception/src/lib.rs80](core/mana-perception/src/lib.rs#L80-L80)


**DepthFrame → region_stats() → RegionStats → DepthRuleSnapshot → FSM DepthRule guards**
DepthRules (TOML) → mana-control → Thresholds → Control Logic

The concrete bridge type between these systems is **`DepthRuleSnapshot`** (`core/mana-control/src/lib.rs:290-309`), built from the raw rule results per cycle and installed into the `ProcessImage`. Rules do **not** gate models (see `config/depth-rules.toml:5`): they only produce evidence consumed by `DepthRule` FSM guards; a rule is silently skipped when `min_valid_ratio` fails.
