The Model Catalog is the central registry for all neural network models available to the `mana-lite` application. It defines the parameters for inference (ONNX paths, confidence thresholds, image sizes), post-processing filters (NMS, area ratios, class filtering), and cropping strategies (static vs. dynamic). The catalog uses a hierarchical, include-based composition pattern to manage complexity across different tasks like detection, pose estimation, segmentation, and depth analysis.

## Configuration Structure

The catalog is defined by a root `models.toml` file which acts as an entry point, including several task-specific files located in the `config/models/` subdirectory [config/models.toml1-10](config/models.toml#L1-L10)

### The Composition Pattern

Configuration is resolved through a layered approach:

1. **Global Defaults**: Defined in `models/base.toml`, providing baseline values for all models (e.g., `device = "cpu"`, `confidence = 0.25`) [config/models/base.toml3-18](config/models/base.toml#L3-L18)
2. **Task Defaults**: Defined at the top of task files (e.g., `models/detect.toml`) to set task-specific baselines like `half = true` for detection [config/models/detect.toml3-6](config/models/detect.toml#L3-L6)
3. **Profiles**: Named sets of configurations (e.g., the `face` profile) that can be shared by multiple model entries to ensure consistency in cropping and post-processing [config/models/detect.toml8-22](config/models/detect.toml#L8-L22)
4. **Model Entries**: The final specific model definition (e.g., `detect-fast`), which inherits from the above layers and overrides specific fields like `path` and `imgsz` [config/models/detect.toml24-41](config/models/detect.toml#L24-L41)

## Key Entities

### ModelEntry

The `ModelEntry` struct represents the fully resolved configuration for a single model [src/config/models.rs45-59](src/config/models.rs#L45-L59)

|Field|Description|Source|
|---|---|---|
|`path`|Path to the `.onnx` model file.|[src/config/models.rs46](src/config/models.rs#L46-L46)|
|`task`|The `ModelTask` (Detect, Pose, Segment, Depth, etc.).|[src/config/models.rs47](src/config/models.rs#L47-L47)|
|`imgsz`|The input resolution for the model (e.g., 320, 640).|[src/config/models.rs52](src/config/models.rs#L52-L52)|
|`confidence`|The primary confidence threshold for inference.|[src/config/models.rs49](src/config/models.rs#L49-L49)|
|`postprocess`|A `PostprocessConfig` for filtering raw detections.|[src/config/models.rs57](src/config/models.rs#L57-L57)|
|`crop`|Optional `CropConfig` for static or dynamic ROIs.|[src/config/models.rs58](src/config/models.rs#L58-L58)|

### PostprocessConfig

This struct controls how raw model outputs are filtered before being passed to trackers or the FSM [src/config/models.rs75-84](src/config/models.rs#L75-L84)

- **`allow_classes`**: A whitelist of class names (e.g., `["person", "face"]`). If empty, all classes are accepted [src/config/models.rs137-141](src/config/models.rs#L137-L141)
- **`min_area_ratio` / `max_area_ratio`**: Filters detections based on their size relative to the frame/crop area. Useful for ignoring tiny background noise or oversized false positives [src/config/models.rs157-162](src/config/models.rs#L157-L162)
- **`nms_iou`**: The Non-Maximum Suppression threshold used to merge overlapping boxes [src/config/models.rs82](src/config/models.rs#L82-L82)

### CropConfig

Defines the region of interest (ROI) where the model should run [src/config/models.rs183-195](src/config/models.rs#L183-L195)

1. **Static Crop**: A fixed rectangular region `[x1, y1, x2, y2]` in the original frame [config/models/detect.toml39-40](config/models/detect.toml#L39-L40)
2. **Dynamic Crop (`largest_class`)**: A crop that follows a specific object detected by a previous model in the cascade (e.g., a `face` model cropping around a `person` box) [config/models/detect.toml18-22](config/models/detect.toml#L18-L22)

## Task-Specific Configurations

### Detection (`detect.toml`)

Primary models for identifying objects. The `face` profile is a key example, defining a `largest_class` crop on `person` with an `upper_fraction` of `0.50` to focus on the head region [config/models/detect.toml18-22](config/models/detect.toml#L18-L22)

### Depth (`depth.toml`)

Models used for spatial analysis. Depth models often use a `static` crop to focus on a specific area (like a bed) to evaluate `DepthRegionRule` snapshots [config/models/depth.toml13-17](config/models/depth.toml#L13-L17)

### Segmentation (`segment.toml`)

Models providing pixel-level masks. Includes `polygon_simplify` settings to control the complexity of the vector contours generated from the masks [config/models/segment.toml27](config/models/segment.toml#L27-L27) [src/config/models.rs56](src/config/models.rs#L56-L56)

## Model Overlays

The system supports a `ModelOverlay` mechanism, allowing a configuration file to `extends` another catalog and override specific model settings without duplicating the entire manifest [src/config/model_loader.rs36-42](src/config/model_loader.rs#L36-L42) This is frequently used in blueprints to customize model behavior for specific deployment scenarios.
