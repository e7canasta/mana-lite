# Zone Engine and Spatial Signals
Este texto describe el funcionamiento del **Zone Engine** y el **Scene Signals System**, dos componentes esenciales que transforman datos espaciales crudos en **contexto semántico** para la toma de decisiones lógica. El primero utiliza **evaluación geométrica** y un mecanismo de **histéresis** para detectar con precisión si objetos confirmados ocupan áreas específicas, evitando notificaciones redundantes o erráticas. Por su parte, el sistema de señales establece un **vocabulario estandarizado** y tipificado que traduce el estado de la escena en datos comparables, como conteos o razones, facilitando la comunicación entre productores de datos y evaluadores lógicos. Finalmente, la obra detalla cómo estos sistemas se integran en un **ciclo de control** secuencial, donde la información se procesa, se utiliza para transiciones de estado y se congela en una **instantánea inmutable** para fines de registro y telemetría.

The **Zone Engine** and **Scene Signals** systems provide the spatial and logical context required for the Finite State Machine (FSM) to make decisions. While the tracking system identifies _what_ and _where_ entities are, these systems translate raw coordinates into semantic meaning (e.g., "is a person in the bed?") and standardized logical observations (e.g., "face confidence is high").

## Zone Engine

The `ZoneEngine` is a geometric evaluation system that determines if specific rectangular regions of interest (Zones) are occupied by confirmed tracks [core/mana-control/src/zones.rs40-42](core/mana-control/src/zones.rs#L40-L42) It manages state transitions for each zone using a hysteresis-based approach to prevent flickering in event emission [core/mana-control/src/zones.rs28-35](core/mana-control/src/zones.rs#L28-L35)

### Geometric Evaluation

Zones are defined as Axis-Aligned Bounding Boxes (AABB). Intersection is determined by the `rect_intersects` utility [core/mana-control/src/zones.rs137-139](core/mana-control/src/zones.rs#L137-L139)

- **Confirmed-Track Gating**: A zone is only considered occupied if the intersecting `Track` has `is_confirmed: true` [core/mana-control/src/zones.rs75-76](core/mana-control/src/zones.rs#L75-L76)
- **Deterministic Ordering**: The engine uses a `BTreeMap<ZoneId, ZoneState>` to ensure that events are emitted in a consistent, alphabetical order by `ZoneId`. This ensures that FSM transitions triggered by multiple zone changes are reproducible [core/mana-control/src/zones.rs37-42](core/mana-control/src/zones.rs#L37-L42)

### Hysteresis and Events

The engine emits `ZoneEvent::Occupied` and `ZoneEvent::Vacated` events [core/mana-control/src/zones.rs10-26](core/mana-control/src/zones.rs#L10-L26)

- **Occupied**: Triggered immediately when a confirmed track enters a vacant zone [core/mana-control/src/zones.rs79-94](core/mana-control/src/zones.rs#L79-L94)
- **Vacated**: Triggered only after a zone has been empty for a duration exceeding its configured `hysteresis_ms` [core/mana-control/src/zones.rs98-114](core/mana-control/src/zones.rs#L98-L114)

## Scene Signals System

The Scene Signals system provides a versioned, type-safe vocabulary for describing the state of the scene. It acts as a bridge between various producers (Occupancy, FSM, Tracking) and consumers (FSM Guards, JSONL Logging).

### Signal Catalog

The `SignalCatalog` defines the static vocabulary of available signals. It is currently hardcoded as `v1` and contains nine tags such as `persona.presente`, `cara.confianza`, and `ocupacion.cardinalidad` [core/mana-control/src/signals/catalog.rs138-185](core/mana-control/src/signals/catalog.rs#L138-L185)

- **SignalTag**: A unique identifier following the `domain.attribute` naming convention [core/mana-control/src/signals/catalog.rs103-117](core/mana-control/src/signals/catalog.rs#L103-L117)
- **SignalPresence**: Defines when a signal should have a value (e.g., `Always`, `WhenFaceSelected`, `WhileFsmActive`) [core/mana-control/src/signals/catalog.rs15-24](core/mana-control/src/signals/catalog.rs#L15-L24)

### Signal Values and Operators

Signals support four specific types via the `SignalValue` enum [core/mana-control/src/signals/value.rs52-57](core/mana-control/src/signals/value.rs#L52-L57):

1. **Bool**: Boolean flags.
2. **Count**: Unsigned 64-bit integers.
3. **Ratio**: Floating point values strictly bounded to `[0.0, 1.0]` [core/mana-control/src/signals/value.rs17-38](core/mana-control/src/signals/value.rs#L17-L38)
4. **Label**: Strings from a closed set defined in the catalog (e.g., `empty`, `single`, `multiple` for occupancy) [core/mana-control/src/signals/catalog.rs174-180](core/mana-control/src/signals/catalog.rs#L174-L180)

Comparisons are performed via `SignalOp` (`==`, `!=`, `>`, `<`, `>=`, `<=`), with strict compatibility checks (e.g., `Ratio` does not support exact equality `==`) [core/mana-control/src/signals/value.rs125-170](core/mana-control/src/signals/value.rs#L125-L170)

### Signal Lifecycle: Table to Snapshot

During a control cycle, signals are gathered into a `SignalTable`. At the end of the cycle, this table is frozen into a `SceneSignalsSnapshot`.

|---|---|---|

## Integration in the Control Loop

The `scan()` loop coordinates these systems in a specific sequence:

1. **Update Zones**: The `ZoneEngine` evaluates the current `Track` list and generates `ZoneEvent` objects [core/mana-control/src/zones.rs68-118](core/mana-control/src/zones.rs#L68-L118)
2. **Evaluate FSM**: The FSM uses the `ZoneEngine` state (via `is_occupied`) and the generated `ZoneEvent` list to process transitions [core/mana-control/src/fsm/tests/zones.rs54-63](core/mana-control/src/fsm/tests/zones.rs#L54-L63)
3. **Emit Signals**: The final state of all systems is captured in the `SceneSignalsSnapshot` and emitted for downstream telemetry [src/logger/event/scene.rs112-141](src/logger/event/scene.rs#L112-L141)
