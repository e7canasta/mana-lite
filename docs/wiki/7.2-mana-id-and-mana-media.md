# mana-id and mana-media
Las bibliotecas **mana-id** y **mana-media** constituyen la infraestructura base de un sistema diseñado para la gestión de datos y el procesamiento de video de alto rendimiento. Por un lado, **mana-id** garantiza la integridad del software mediante **identificadores de dominio con seguridad de tipos**, utilizando macros y contenedores de cadenas compartidas para evitar confusiones lógicas y permitir búsquedas eficientes. Por otro lado, **mana-media** optimiza el flujo de video a través de una **gestión de memoria mediante BufferPool**, que recicla recursos para evitar la sobrecarga de asignaciones constantes durante la decodificación. Finalmente, el sistema facilita la interoperabilidad con estándares industriales mediante el rasgo **FrameDecoder** y herramientas para la detección de **tramas IDR en H.264**, asegurando una transferencia de datos fluida y determinista en todo el ecosistema.

The `mana-id` and `mana-media` crates provide the foundational types and traits for system-wide identification and media handling. These crates are categorized as **T0/T1** (Tier 0/1) libraries, meaning they have zero dependencies on higher-level logic crates like `mana-control` or `mana-perception`, ensuring they can be shared across the entire workspace without circular dependencies [std/mana-media/src/lib.rs7-8](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/lib.rs#L7-L8)

## 1. mana-id: Type-Safe Domain Identifiers

`mana-id` implements a mechanism for domain-specific string identifiers (e.g., `ModelId`, `ZoneId`, `StateId`) to prevent type confusion while maintaining the performance of shared string allocations.

### DomStr and domain_id! Macro

The core of this crate is the `DomStr` newtype, which wraps an `Arc<str>` [std/mana-id/src/lib.rs14](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L14-L14) This allows for zero-copy cloning and sharing of identifier strings across threads [std/mana-id/src/lib.rs241-245](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L241-L245)

The `domain_id!` macro is used to generate specific identifier types. These types:

- **Prevent Interchangeability**: A `ModelId` cannot be accidentally passed to a function expecting a `ZoneId` [std/mana-id/src/lib.rs259-261](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L259-L261)
- **Enable Determinism**: They implement `Ord` and `PartialOrd` based on the underlying string, allowing them to be used as keys in `BTreeMap` for deterministic iteration in the control loop [std/mana-id/src/lib.rs52-58](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L52-L58)
- **Support Efficient Lookup**: They implement `Borrow<str>`, which ensures that `HashMap<Id, V>::get("string_literal")` works correctly by hashing the string identically to the ID [std/mana-id/src/lib.rs79-83](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L79-L83) [std/mana-id/src/lib.rs210-218](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-id/src/lib.rs#L210-L218)

## 2. mana-media: Frame Transport and Decoding

`mana-media` defines the data structures and traits for video ingest, frame representation, and memory management.

### Frame Representation

The crate defines how frames are moved through the pipeline using two primary structures:

1. **`RawFrameV1`**: A header containing metadata such as `frame_id`, `timestamp_ns`, `width`, `height`, and `pixel_format` [std/mana-media/src/frame.rs55-65](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/frame.rs#L55-L65)
2. **`DecodedFrame`**: A container combining the `RawFrameV1` header with a `Vec<u8>` of raw pixel bytes [std/mana-media/src/lib.rs101-104](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/lib.rs#L101-L104)

### Pixel Formats

The `PixelFormat` enum supports various layouts, including `Rgb8`, `Bgr8`, and `Nv12` [std/mana-media/src/frame.rs5-14](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/frame.rs#L5-L14) It provides utility methods to calculate the expected byte size for a given resolution, including special handling for semi-planar `Nv12` (Y plane + interleaved UV plane) [std/mana-media/src/frame.rs44-51](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/frame.rs#L44-L51)

### Buffer Management: BufferPool

To eliminate the performance penalty of `malloc(6MB) + free(6MB)` churn on every frame in high-resolution streams, `mana-media` provides a `BufferPool` [std/mana-media/src/buffer_pool.rs3-6](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/buffer_pool.rs#L3-L6)

- **Acquisition**: The ingest engine takes a `Vec<u8>` from the pool [std/mana-media/src/buffer_pool.rs74-84](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/buffer_pool.rs#L74-L84)
- **Reuse**: After the frame is processed, the buffer is `release`d back to the pool, where it is cleared but retains its capacity [std/mana-media/src/buffer_pool.rs98-115](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/buffer_pool.rs#L98-L115)
- **Boundedness**: The pool has a `max_bufs` limit to prevent memory leaks in error paths; excess buffers are dropped [std/mana-media/src/buffer_pool.rs120-126](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/buffer_pool.rs#L120-L126)

### Frame Processing Logic

#### Media Data Flow

"Ingest Engine" -> "FrameDecoder" : "next_frame()" "FrameDecoder" -> "BufferPool" : "acquire()" "FrameDecoder" -> "FFmpeg/H.264" : "Decode Bitstream" "FrameDecoder" -> "DecodedFrame" : "Pack pixels into buffer" "Ingest Engine" -> "Inference Pipeline" : "Send DecodedFrame" "Inference Pipeline" -> "BufferPool" : "release(buffer)"

## 3. Video Decoding and H.264 Helpers

### FrameDecoder Trait

The `FrameDecoder` trait provides a unified interface for all video sources (RTSP, File, etc.) [std/mana-media/src/lib.rs118](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/lib.rs#L118-L118)

- `next_frame()`: An async method returning a `Result<DecodedFrame, FrameDecoderError>` [std/mana-media/src/lib.rs120-122](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/lib.rs#L120-L122)
- Metadata methods: `width()`, `height()`, `pixel_format()`, and `fps()` [std/mana-media/src/lib.rs125-131](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/lib.rs#L125-L131)

### H.264 Annex-B IDR Detection

The `h264` module contains `contains_idr`, a utility to scan raw bitstreams for H.264 Instantaneous Decoder Refresh (IDR) frames (NAL unit type 5) [std/mana-media/src/h264.rs1-11](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/h264.rs#L1-L11) This is used by the ingest engine to identify keyframes for synchronization or selection without full decoding. It supports both 3-byte (`00 00 01`) and 4-byte (`00 00 00 01`) Annex-B start codes [std/mana-media/src/h264.rs7-21](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/h264.rs#L7-L21)

### FFmpeg Integration (Optional)

When the `ffmpeg` feature is enabled, the crate provides:

- **`parse_pixel_format`**: Maps TOML config strings (e.g., "rgb24") to `PixelFormat` and `ffmpeg_next::format::Pixel` [std/mana-media/src/format.rs16-25](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/format.rs#L16-L25)
- **`pack_frame_into`**: A critical utility that copies data from padded FFmpeg frames into tightly-packed `Vec<u8>` buffers [std/mana-media/src/format.rs43-57](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/format.rs#L43-L57) It explicitly handles `stride` (padding for SIMD alignment) to prevent image shearing [std/mana-media/src/format.rs29-33](https://github.com/kerrvisiona-sudo/endeli/blob/ad24740d/std/mana-media/src/format.rs#L29-L33)
